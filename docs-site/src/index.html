Trust Infrastructure · /v1

Authorize AI transactions before they move money.

A deterministic, explainable, Ed25519-signed APPROVE / DENY / REVIEW decision you call before your payment provider. This service never moves, holds, or settles money — it answers the authorization question the payment rails don't.

Quickstart

Key → first authorize in under 15 minutes. Seven steps.

  1. Get an API key

    Mint a test key (test keys are advisory / shadow by default — they never block). Prefixes are azn_test_ and azn_live_; only sha256(key) is stored server-side.

    go run ./cmd/authz-keygen -env test -org org_demo -tier default
# add -enforce to mint an enforcing key; -insert (with DATABASE_URL) to persist it

    Or create one in the dashboard (shown once, then revocable).

  2. Install the SDK

    pip install trust-infra-sdk
    npm install @trust-infra/sdk

  3. Point at the API and load the public keys

    The decision signature is verified against the published Ed25519 keys (GET /v1/keys/public, JWKS). Pass them in, or let the SDK fetch them once.

    from trust_infra import Client, OnUnavailable

client = Client(
    api_key="azn_test_...",
    base_url="https://api.trust-infra.dev",   # or http://localhost:8080
    on_unavailable=OnUnavailable.FAIL_CLOSED,  # default
)
    import { Client, OnUnavailable } from "@trust-infra/sdk";

const client = new Client({
  apiKey: "azn_test_...",
  baseUrl: "https://api.trust-infra.dev", // or http://localhost:8080
  onUnavailable: OnUnavailable.FailClosed, // default
});

  4. Authorize before your payment — and enforce the verdict

    The whole integration is three lines. The SDK canonicalizes + HMAC-signs the request, verifies the signed decision, and enforce() throws unless the verdict is an enforceable APPROVE.

    txn = {
    "agent_id": "procurement-agent-v2",
    "action": "payment.create",
    "amount": "1200.00",          # decimal STRING, never a float
    "currency": "USD",
    "target": {"type": "vendor", "id": "acme-supplies"},
    "idempotency_key": "idem_01HXYZ...",
}

client.authorize(txn).enforce()   # raises DecisionDeniedError unless APPROVE
charge(txn)                       # your existing payment call, reached only on APPROVE
    const txn = {
  agent_id: "procurement-agent-v2",
  action: "payment.create",
  amount: "1200.00",            // decimal STRING, never a float
  currency: "USD",
  target: { type: "vendor", id: "acme-supplies" },
  idempotency_key: "idem_01HXYZ...",
};

(await client.authorize(txn)).enforce();  // throws unless APPROVE
await charge(txn);                         // reached only on APPROVE

  5. De-risk with shadow mode first

    Shadow mode evaluates and logs the decision but never blocks. Run it on one agent, review the audit log, then flip to authorize().enforce(). (Test keys are shadow by default.)

    decision = client.shadow(txn)     # evaluated + logged, never enforced
log.info("would have been %s", decision.verdict.value)
charge(txn)                       # payment path untouched
    const decision = await client.shadow(txn); // evaluated + logged, never enforced
console.log(`would have been ${decision.verdict}`);
await charge(txn);                          // payment path untouched

  6. Read the audit log

    Every decision is a stored, tamper-evident record. List them, or fetch one by id — the receipt is the demo.

    GET /v1/decisions?agent_id=procurement-agent-v2&verdict=DENY
GET /v1/decisions/{decision_id}

    See the decisions endpoints in the reference.

  7. Verify a decision signature

    Anyone — you, an auditor, a regulator — can verify a decision against the published Ed25519 public key, with no shared secret. Tampering with any signed field fails verification.

    from trust_infra import verify_decision, SignatureVerificationError

try:
    verify_decision(decision, jwks)   # or client.verify_decision(decision)
except SignatureVerificationError:
    ...  # tampered or not ours — do not trust
    import { verifyDecision, SignatureVerificationError } from "@trust-infra/sdk";

try {
  verifyDecision(decision, jwks);   // or client.verifyDecision(decision)
} catch (e) {
  if (e instanceof SignatureVerificationError) { /* tampered or not ours */ }
}

Verdicts

Every authorize call returns exactly one verdict (all are HTTP 200). Combination algebra (TRD §5): any hard DENY ⇒ DENY; else any REVIEW ⇒ REVIEW; else all-satisfied ⇒ APPROVE.

VerdictMeaningWhat the caller does
APPROVEAll rules satisfied.Proceed with the payment. Honor any obligations (e.g. capture_within).
DENYA hard rule denied it.Block. enforce() raises. Read explanation for the denying rule.
REVIEWNeeds a human / step-up.Hold for approval; do not auto-proceed. Not an APPROVE.

Fail-mode guidance

The decision plane never guesses. When it's unreachable or returns 503, your on_unavailable policy decides. Fail-mode results are synthetic, unsigned, and flagged degraded.

ModeWhen unavailableUse when
FAIL_CLOSED (default)Synthetic DENY — enforce() blocks the payment.The payment path. Safety first.
FAIL_OPENSynthetic APPROVE — explicit, logged, degraded, unsigned.Availability > control for this flow. Opt-in, eyes open.
LOCAL_CACHEReplays the last signed decision for this idempotency_key; on a miss, fails closed.Idempotent retries that must survive a brief outage.
Guarantee: the SDK never turns an upstream failure into a silent APPROVE. The only way to approve during an outage is to explicitly choose FAIL_OPEN.

Two signatures, kept distinct

Request auth — HMAC (symmetric)

Caller → us. X-Api-Key, X-Signature (HMAC-SHA256 over the canonical payload), X-Nonce, X-Timestamp. The SDK does this for you. Scheme azn-hmac/1.

Decision receipt — Ed25519 (asymmetric)

Us → everyone. The Decision.signature object, verifiable against the published public key with no secret. Scheme ti-decision-canon/1. HMAC here would let a key-holder forge decisions — forbidden.
